# trail-race-planner

Trail race planning tool that estimates finish times and builds checkpoint-based pacing plans from GPX courses and runner performance data.

**版本：** 0.1

**日期：** 2026-11-06

**状态：** GitHub Pages 静态网页 MVP；预测和个人校准仍属原型假设，待更多赛后数据回测验证

---

## 1. 产品摘要

### 一句话

帮助越野跑者根据自己的能力和比赛路线，估算完赛时间，并生成能带进比赛当天使用的分段、补给站和关门时间计划。

### 用户问题

越野跑者赛前通常能拿到 GPX、距离、累计爬升和补给站资料，但很难把这些信息转成可信的个人完赛预估。相同距离和爬升的比赛，路面技术性、坡度分布、海拔、天气和补给站停留都可能不同；公路跑配速计算器往往无法回答“我在这场具体的越野赛大约跑多久、每段应该怎么安排”。

### 产品主张

> 上传比赛路线，补充你的近期跑步表现，得到有依据、可调整的完赛时间范围和分段计划。

产品不承诺精确预言成绩。它展示估算区间、关键假设和主要不确定因素，帮助用户做更好的赛前决策。

### 初期产品形态

先做移动端友好的网页 MVP。无需先开发原生 App、社交网络或完整训练计划系统。验证预测是否有用、计划是否会被采用，以及用户是否愿意为具体赛事规划付费。

---

## 2. 目标与非目标

### MVP 目标

1. 用户能上传赛事 GPX，并确认路线距离和爬升等基础信息。
2. 用户能用少量输入描述自己的能力，至少包括 ITRA Performance Index 或近期比赛成绩。
3. 系统能给出可解释的完赛时间区间和不同目标情境。
4. 系统能生成分段和补给站预计通过时间，帮助用户制定比赛计划。
5. 用户能保存、导出或打印计划，并在赛后反馈实际成绩，用于后续校准。

### MVP 暂不处理

- 训练计划和日常训练负荷管理。
- 实时比赛导航、定位追踪和紧急救援功能。
- 自动抓取所有赛事和赛事 GPX。
- 社交动态、排行榜、俱乐部功能。
- 医疗诊断、伤病建议、个性化营养处方。
- 声称 AI 能准确预测天气、路况或比赛结果。

## 3. 目标用户与使用场景

### 主要用户

**有一定比赛经验的越野跑者**，计划参加一场陌生赛事，能找到官方 GPX 或赛事资料，但不确定自己的合理完赛目标和分段节奏。

典型特征：

- 参加过路跑、越野赛或超马，至少有一项可用于估算能力的近期成绩。
- 关注 ITRA Performance Index、UTMB Index 或类似水平指标，但不一定理解它们的适用范围。
- 会使用手表、GPX、赛事官网、电子表格或教练建议做赛前规划。
- 需要在目标成绩、关门时间、补给节奏和体力分配之间作取舍。

### 次要用户

- 第一次参加越野赛、希望判断目标是否现实的跑者。
- 教练或跑团领队，需要快速查看运动员的赛事计划。
- 赛事组织者，希望给参赛者提供个人化的通过时间规划工具。

### 核心场景

> 我报名了一场 50 公里越野赛，赛事网站提供 GPX 和补给站信息。我有 ITRA 表现指数，也跑过几场比赛。我想知道合理的完赛时间大概是多少、哪些赛段容易掉速、每个补给站大约几点到，以及在关门时间前有多少余量。

## 4. 用户需要完成的工作

1. **理解路线：** 这场比赛的难点在哪里，而不只是总距离和总爬升是多少？
2. **估算成绩：** 结合我的能力，这场比赛的合理完赛时间范围是什么？
3. **制定计划：** 每个赛段或补给站的目标通过时间是什么？
4. **管理风险：** 哪些环节最可能让我落后于计划，关门余量有多大？
5. **赛后学习：** 我的实际结果与预测差多少？下次如何调整估算？

## 5. 产品原则

### 5.1 先可信，再智能

完赛预测是定量问题。核心预测应使用可检查、可回测的统计或规则模型。生成式 AI 可解释路线特征、整理资料、回答用户追问，但不应单独凭 GPX“猜”成绩。

### 5.2 给区间，不制造虚假精度

输出“目标区间 + 情境假设”，避免把单一时间展示成承诺。例如：保守 / 目标 / 理想三种情境，并说明各自建立在什么假设上。区间宽度应由实际回测校准，不能预先承诺固定误差。

### 5.3 解释每个重要判断

用户应能看到路线分析、能力输入和关键假设如何影响结果。系统不应只输出一个不可质疑的数字。

### 5.4 以赛道为单位设计

越野赛计划应按路线分段、爬坡、下坡、补给站和关门时间组织，而不是把公路跑的均匀配速直接套到山地赛事上。

### 5.5 尊重数据来源与隐私

清楚标识 GPX 来源、数据更新时间、用户提供的训练/比赛数据用途和删除方式。未经许可不复制赛事路线或赛事资料。

## 6. 核心用户流程

### 流程 A：创建比赛计划

1. 用户选择“新建比赛计划”。
2. 输入赛事名称、日期、赛事起跑时间、时区；可跳过非必需项。
3. 上传 GPX。
4. 系统解析路线并展示地图、距离、高程曲线、累计爬升/下降及数据质量提示。
5. 用户确认赛事官方距离与爬升；若 GPX 统计与赛事资料差异较大，系统提示选择采用哪组数据。
6. 用户添加补给站、关门时间和预计停留时间。可手动添加，也可从赛事资料粘贴/导入。
7. 用户选择能力输入方式：
   - ITRA Performance Index；或
   - 近期比赛成绩、距离、赛事类型和日期；或
   - 进阶用户上传历史活动文件（后续版本）。
8. 用户补充近期训练情况及少数影响因素，例如长距离经验、爬升训练、类似赛事经验。MVP 可设为可选字段。
9. 系统生成初步预测与计划。
10. 用户切换保守 / 目标 / 理想情境，调整补给站停留时间或目标强度。
11. 用户保存、打印或导出计划。

### 流程 B：赛后校准

1. 用户打开已保存的计划，选择“录入实际成绩”。
2. 输入完赛时间、补给站实际通过时间（可选）、比赛中断或异常情况（可选）。
3. 系统对比预测和实际成绩，展示偏差主要出现在前半程、后半程还是停留时间。
4. 用户授权后，该数据可用于匿名化模型评估；用户能撤回授权或删除个人数据。

## 7. MVP 功能需求

### 7.1 GPX 上传与解析

**必需：**

- 支持 GPX 文件上传；提示文件大小和格式限制。
- 校验文件可读性、轨迹点数量、坐标范围和时间戳情况。
- 展示轨迹地图、里程、高程曲线、累计爬升/下降。
- 识别路线中的主要上坡、下坡和长距离缓坡区段。
- 让用户确认/修正距离、起点和终点；保留官方公布数值与 GPX 计算值的区别。
- 对缺少高程、轨迹断点、异常 GPS 抖动等情况给出明确提示。

**注意：** GPX 高程会受设备、采样和地图高程模型影响。不得把一次计算的爬升数字呈现为赛事官方数据。应同时显示“赛事公布值”和“文件计算值”，并说明采用值。

### 7.2 跑者能力档案

**MVP 必填其一：**

- ITRA Performance Index；或
- 一项近期比赛结果：距离、用时、比赛类型、比赛日期。

**可选输入：**

- 近期每周跑量范围。
- 近期每周爬升范围。
- 最近最长训练距离/时长。
- 类似距离或类似地形的完赛经验。
- 目标赛事是否是高海拔、夜赛或多日赛。

系统需要解释缺少数据时预测区间会更宽。不要把 ITRA Endurance Points（赛事难度点）误当成跑者能力指标。

### 7.3 路线难度与结构分析

MVP 可从 GPX 可靠计算或近似得出：

- 距离、累计爬升/下降。
- 坡度分布、主要爬升与下降区段。
- 海拔范围和高海拔暴露情况（仅当坐标和高程数据可靠时）。
- 路线分段建议，默认可按 5 公里、补给站或主要地形变化切分。

后续再逐步加入：地面技术性、路面类型、技术下坡、泥雪/涉水、遮阴、路况季节性。若数据来源不足，应标为未知，不能从 GPX 几何形状推断出“技术难度”。

### 7.4 完赛时间预测

输出：

- 保守、目标、理想三种情境的完赛时间范围。
- 预测置信度/数据充分度提示（例如“初步估算”或“有多场相似比赛可参考”）。
- 预测基于的跑者输入和赛道输入。
- 对预测最敏感的因素说明。

预测逻辑建议分层：

1. **基线能力估算：** 根据跑者近期成绩或 ITRA PI 建立基线能力。
2. **赛道调整：** 根据距离、爬升/下降分布、海拔和赛道类型调整，不以总爬升一个数字概括全部难度。
3. **超长距离衰减：** 对长距离引入疲劳衰减，并使用相似赛事或相似跑者历史结果校准。
4. **停留时间：** 将补给站停留时间作为单独组成部分计算，允许用户自定义。
5. **情境区间：** 用历史误差和可选情境假设形成区间，而非声称精确到分钟。
6. **校准：** 赛后保存赛前预测和实际成绩，比较误差并用于后续估算。当前静态 MVP 仅在用户本机浏览器保存记录，使用最近最多 5 场的实际/预测比值做收缩平均校准，至少 2 场后启用，修正幅度限制在 ±10%。这属于个人偏差修正，不会上传数据，也不会训练或更新全局 AI 模型。

初期数据不足时，可以从规则模型和公开/授权的赛事结果数据开始，清楚标注预测成熟度。模型达到足够样本量前，不宣传“AI 精准预测”。

### 7.5 分段与补给站计划

- 自动建议分段点：补给站、主要爬升/下降、用户指定距离间隔。
- 每段展示距离、爬升/下降、目标用时范围和累计通过时间。
- 补给站展示预计到达时间、预计停留时间、预计离开时间。
- 关门点展示预计余量；若目标计划无法满足关门时间，明确标红并说明原因。
- 支持用户修改停留时间、目标情境和计划起跑时间，并实时更新后续时间。
- 可导出 PDF/打印版；手表同步、GPX 内嵌配速点后置。

### 7.6 解释与 AI 助手

MVP 的 AI 助手围绕已计算结果解释，不直接替代计算引擎。可支持：

- “这场比赛的主要难点是什么？”
- “为什么后半程预估变慢？”
- “如果每个补给站多停 5 分钟，完赛时间和关门余量会怎样？”
- “我的目标时间风险最大的是哪一段？”

每个回答需引用本次计划里的具体路线数据或用户输入；数据不足时明确说“无法判断”。AI 不提供医疗诊断、伤病处置或保证安全的承诺。

## 8. 预测输入、输出与限制

| 类别     | MVP 输入/输出                                  | 备注                                     |
| -------- | ---------------------------------------------- | ---------------------------------------- |
| 跑者水平 | ITRA Performance Index 或近期比赛成绩          | ITRA PI 是能力代理指标，不是完赛时间保证 |
| 跑者耐力 | 近期跑量、最长训练、相似赛事经验（可选）       | 缺失时扩大不确定区间                     |
| 赛道     | GPX 距离、高程曲线、爬升/下降分布              | GPX 高程可能有误差                       |
| 赛事运营 | 补给站、关门时间、停留时间                     | 由用户核对赛事官方资料                   |
| 环境     | GPX 海拔；用户选择天气/路面情景和预计夜跑时长 | 当前为可解释的启发式系数，不是天气预报；赛后校准仅限本机 |
| 输出     | 时间区间、分段通过时间、关门余量、关键风险因素 | 清楚说明数据和假设                       |

### 当前 MVP 的预测与个人校准

- 环境调整是用户主动选择的规划情景：常规路况 +0%、小雨/湿滑 +5%、强降雨/泥泞 +12%、高温闷热 +10%；夜跑每小时增加约 2%，最多 +10%。天气与夜间增量相加，环境影响只乘在移动时间上，CP 停留另计。
- 这些百分比是原型启发式假设，没有足够的历史赛事数据回测。不同温度、雨量、海拔、赛道暴露和个人适应差异很大；用户可以选择最接近的情景，不能将结果当作精确天气影响。
- 点击生成计划时，待完赛计划（赛事名称、目标预测、距离/爬升、环境情景和保存时间）写入浏览器 `localStorage`；GPX 文件本身不会保存。重新打开同一浏览器后可恢复待回填计划。赛后录入实际成绩后，记录赛事名称、赛前预测、实际用时及环境输入。最近最多 5 场记录的实际/预测时长比值经收缩后形成个人修正，至少 2 场才启用，最大修正幅度 ±10%。
- 校准针对单个浏览器中的个人历史，清除浏览器站点数据会删除记录；不同设备/浏览器间不会同步。页面提供清除本机记录入口。记录不会发送给产品方，不能据此称为全局 AI 学习。

### 预测边界

- 没有技术路面、天气、赛事结果或训练历史时，预测只能是初步估算。
- GPX 不能可靠说明赛道的泥泞、碎石、拥挤、路权变化或临时封闭。
- 伤病、睡眠、补给耐受、装备故障、天气突变等变量会显著改变结果；目前环境系数只做粗略情景调整。
- 结果用于规划参考，用户仍需核对赛事方最新信息并自行判断。

## 9. 关键页面草图说明

### 9.1 首页 / 我的比赛

- 主按钮：新建比赛计划。
- 已保存赛事卡片：赛事名、日期、距离、目标时间、计划状态。

### 9.2 上传与路线确认页

- GPX 上传区。
- 地图和高程图。
- “赛事公布”与“GPX 计算”数据并列。
- 数据质量提示和纠正入口。

### 9.3 跑者信息页

- ITRA PI 输入框及解释链接。
- 近期成绩输入选项。
- 训练信息简表，可跳过。
- 隐私说明：何种资料保存、用途和删除方式。

- 三个情境卡片：保守 / 目标 / 理想。
- 总完赛时间范围与数据充分度。
- 路线难点摘要。
- 预测组成：移动时间、补给停留、环境/经验调整（仅展示有数据的因素）。

- “调整假设”入口。
- 完赛后回填实际用时，展示与赛前目标预测的偏差，并保存个人校准记录。

- 赛事基本信息与计划版本。
- 每个赛段、补给站的累计距离、爬升、目标到达/离开时间。
- 关门时间和余量。
- 明确标注“估算计划，请以赛事方最新公告为准”。

## 10. 数据策略与冷启动

### 10.1 可用数据来源

- 用户自行上传的 GPX 和成绩。
- 赛事方授权的路线、补给站、关门点与赛果。
- 公开授权或允许再利用的赛事结果数据。
- 跑者自愿提供且明确授权用于模型评估的数据。

### 10.2 冷启动策略

1. 选择一个越野赛事活跃的地区或赛事类型，不追求一开始覆盖全球。
2. 邀请 30–50 位跑者带着已完成赛事的 GPX 和成绩做历史回测。
3. 优先覆盖常见距离段和清晰的官方路线资料。
4. 找教练、跑团或赛事组织者做小范围试用，获得经过核对的赛道和赛事运营数据。
5. 每条路线记录来源、版本、最后核对日期和数值采用规则。

### 10.3 数据质量治理

- GPX 来源、授权状态和创建日期。
- 文件距离/爬升与赛事公布值的差异。
- 补给站及关门信息的来源与更新时间。
- 用户可请求删除其个人资料和上传文件。
- 默认不公开个人 GPX、训练活动或历史成绩。

## 11. 商业模式假设

优先验证用户是否愿意为“单场比赛的有效计划”付费，而不是先假设订阅一定成立。

### 可能方案

1. **免费基础分析 + 单场付费计划：** 免费查看路线摘要，付费解锁分段、补给站和可打印计划。
2. **订阅：** 适合一年参加多场比赛、要保存多个计划并做赛后复盘的跑者。
3. **教练版：** 教练管理多名跑者和多个赛事计划。
4. **赛事方合作：** 为赛事提供参赛者计划生成页，或联合提供经授权的路线资料。

### 早期验证方式

- 访谈时询问用户最近一次做计划用了什么工具、花了多久、实际使用了哪些内容。
- 用可点击原型测试结果页和分段计划是否解决问题。
- 在工具中测试真实价格和购买意愿，不只问“你会不会付费”。
- 比较按场次付费和订阅的实际转化。

## 12. 成功指标与验证计划

### 12.1 价值验证指标

- GPX 上传后成功生成可用计划的比例。
- 用户保存、打印或导出的比例。
- 用户是否将分段/补给计划带入比赛。
- 赛后成绩回填率。
- 用户认为计划有帮助的比例，以及具体帮助在哪。
- 复用率：同一用户是否为第二场比赛创建计划。
- 付费转化率、单场购买率或订阅留存。

### 12.2 预测质量指标

- 预测完赛时间与实际完赛时间的绝对误差和相对误差。
- 预测区间覆盖率：实际成绩是否落在预测区间内。
- 按距离、爬升、海拔、经验水平分组观察误差。
- 对完赛与否、关门风险的识别表现。
- 与用户自我估计、简单距离/爬升规则的基线对比。

数据量不足时，不将小样本结果宣传为普遍准确率。预测区间如果过宽而失去用途，或过窄却经常漏掉实际成绩，都说明模型仍需改进。当前本机校准数据不会回传，项目方暂时无法汇总计算总体误差；若要开展跨用户模型改进，需先接入服务端并明确征得用户授权、说明用途和删除方式。

### 12.3 建议的 6 周验证节奏

**第 1 周：问题访谈**
访谈 15–20 位近期参加越野赛的跑者，收集他们赛前用什么方法估时、怎样安排补给、最不确定的决策和赛后偏差。

**第 2 周：原型评审**
制作上传路线、能力输入、预测结果和分段表的可点击原型，邀请 5–8 人完成任务并观察卡点。

**第 3–4 周：人工辅助 MVP**
先用 GPX 解析和半自动预测生成计划，可由团队人工核对路线资料。避免先开发不确定的自动数据抓取。

**第 5 周：历史回测**
收集有完整 GPX 和实际成绩的已完赛赛事，严格模拟赛前可用信息，计算误差并记录不适用情形。

**第 6 周：真实赛事试用**
找一批即将参赛的用户使用计划。比赛结束后收集实际分段、完赛时间和计划采纳情况，再决定是否投入原生 App 和更复杂的 AI 能力。

## 13. 风险与应对

| 风险                        | 影响                   | 应对                                                     |
| --------------------------- | ---------------------- | -------------------------------------------------------- |
| 预测不准或区间没有校准      | 失去用户信任           | 先做历史回测；显示范围、假设和数据充分度                 |
| GPX 高程误差                | 路线难度和分段时间偏差 | 对比官方数据；提示来源；允许修正                         |
| 赛道技术性/路况缺失         | 仅凭距离爬升低估难度   | 标记未知；通过赛事方和用户反馈逐步补数据                 |
| 赛事资料过期                | 补给和关门计划错误     | 显示来源与更新时间；提示用户临赛核对官方公告             |
| 赛事 GPX 和赛果版权问题     | 需要下架或承担法律成本 | 取得授权，尊重来源条款，不默认复制商业赛事资料           |
| 上传健康/训练数据的隐私顾虑 | 降低注册与上传意愿     | 最小化收集；明确同意；提供删除和导出；默认私有           |
| 过度依赖生成式 AI           | 产生无依据的建议       | 模型计算结构化结果；AI 只解释并回答有数据依据的问题      |
| 用户把计划当成安全保证      | 不恰当依赖             | 结果标注估算性质；提示核对官方信息；不声称救援或安全保障 |

## 14. 技术与实现建议（MVP）

### 前端

- 响应式 Web，优先适配手机浏览器。
- 上传 GPX、地图轨迹、高程曲线、可编辑分段表。
- 计划支持打印和 PDF 导出。

### 后端与计算

- GPX 解析、轨迹清洗和分段计算独立于生成式 AI。
- 预测算法以版本化方式运行，保存输入快照和模型版本，便于赛后评估。
- 所有时间输出保留计算依据和不确定度来源。
- 地图、地形和高程服务需核实商业使用条款、缓存政策和离线使用许可。

### AI 使用范围

- 以结构化路线摘要和模型输出作为上下文生成解释。
- 不让模型自行编造路线信息、赛事规则或天气。
- 对无法由输入支持的问题回答“目前资料不足”。
- 每次 AI 回答可追溯到路线或用户资料中的依据。

## 15. 关键待验证假设

1. 跑者最需要的结果是完赛时间预测，还是补给站/分段执行计划？
2. ITRA PI 是否足以作为多数用户的起步能力输入？用户是否更愿意输入比赛成绩？
3. 用户是否愿意上传历史活动或比赛结果来换取更好的预测？
4. 用户能否接受给出时间范围，而不是单一目标成绩？
5. 对哪个距离段，预测价值和付费意愿最高？（例如 50K、100K 或百英里）
6. 跑者是否愿意赛后回填数据，让产品持续校准？
7. 用户会更愿意按场次付费、订阅，还是由教练/赛事方付费？
8. 早期最能建立信任的数据来源是什么：官方赛事资料、历史完赛结果、当地跑者经验，还是个人训练数据？

---

## 16. 当前建议

建议以“**GPX + 跑者能力 → 可解释的完赛区间 + 可执行的分段计划**”作为 MVP。先聚焦一个赛事距离区间或一个跑者群体，不做全面训练平台。预测模型用历史数据回测，生成式 AI 负责解释结果和帮助调整假设。等用户愿意重复使用、回填赛后成绩，并且预测区间经回测表现稳定，再扩展天气、训练数据整合、教练协作和手表同步。

本产品是否成立，最终看三件事：

1. 预测是否比用户现有估法更有参考价值；
2. 分段计划是否真的被带到比赛当天使用；
3. 用户是否愿意在第二场比赛继续回来使用或付费。
